# ロードマップ v1(バージョンと達成条件) — ドラフト

前提: ADR-016〜028。docs/07 のフェーズ P0〜P6 は作業単位、本書は**公開物のバージョンと合格条件**。互換性は L1〜L4(ADR-028)で分けて測る。
状態: ドラフト(STEP2 レビュー前)。ユーザー提示の v0.1〜v1.0 案をベースに、測定可能な形へ書き直した。

## 1. 合格の測り方(全バージョン共通)
- **台帳**: `docs/coverage/*.csv`(基準 WP から機械的に列挙。列: id,name,category,compat_level,status,notes)。status は todo / done / wontfix(理由必須)。
- **合格率** = done ÷ (全件 − wontfix)。各バージョンは「対象カテゴリの合格率」と「E2E 比較の通過」の両方で判定する。
- **E2E 比較**(docs/07): E1 REST/feed/sitemap、E2 ブロック HTML、E3 テーマ描画(+画面差分)、E4 管理操作の副作用。基準 WP=OCI 上の 7.1.3。
- 差異は `docs/parity-exceptions.md` に理由付きで一覧化したものだけ許容。

## 3. 設計上の論点
1. **フックモデルが SDK と Bridge の土台**: PHP プラグインのフックと TS SDK のフックが別物だと二重実装になる。先に TS 側のモデル(優先度・引数・戻り値の規約)を固め、Bridge はそれへ写像する。
2. **L4 は最大リスク**: 方式未決(ADR-028)。v0.3 までに成立性スパイクを別計画で実施。結果次第で v0.5 の範囲を縮小。
3. **対象範囲の固定が先**: 「完全互換」を目標としても、各版の対象は台帳の部分集合として固定する(コアブロック、REST ルート、テンプレート階層)。
4. **v0.6 は台帳が機械可読であることが前提**。

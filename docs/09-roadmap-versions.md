v1 は GPT-6.1-sol の STEP2 レビューで No-Go(Blocker3/Major4/Minor1)。本版は §5 の対応で修正した。

前提: ADR-016〜028。docs/07 のフェーズ P0〜P6 は作業単位、本書は**公開物のバージョンと合格条件**。互換性は L1〜L4(ADR-028)で分けて測る。
状態: ドラフト(STEP2 レビュー前)。ユーザー提示の v0.1〜v1.0 案をベースに、測定可能な形へ書き直した。

## 1. 合格の測り方(全バージョン共通)
- **台帳**: `docs/coverage/*.csv`(基準 WP から機械的に列挙。列: id,name,category,compat_level,status,notes)。status は todo / done / wontfix(理由必須)。
- **合格** = 版ごとに凍結した対象 ID の **100%** が done(証跡付き)かつ必須 E2E 通過。wontfix は理由+ユーザー承認(§5.1)。
- **E2E 比較**(docs/07): E1 REST/feed/sitemap、E2 ブロック HTML、E3 テーマ描画(+画面差分)、E4 管理操作の副作用。基準 WP=OCI 上の 7.1.3。
- 差異は `docs/parity-exceptions.md` に理由付きで一覧化したものだけ許容。

## 3. 設計上の論点
1. **フックモデルが SDK と Bridge の土台**: PHP プラグインのフックと TS SDK のフックが別物だと二重実装になる。先に TS 側のモデル(優先度・引数・戻り値の規約)を固め、Bridge はそれへ写像する。
2. **L4 は最大リスク**: 方式未決(ADR-028)。v0.3 までに成立性スパイクを別計画で実施。結果次第で v0.5 の範囲を縮小。
3. **対象範囲の固定が先**: 「完全互換」を目標としても、各版の対象は台帳の部分集合として固定する(コアブロック、REST ルート、テンプレート階層)。
4. **v0.6 は台帳が機械可読であることが前提**。

## 5. レビュー対応(v1 No-Go → v2)
1. **[Blocker] 達成条件の固定**: 各版は「対象 ID リスト」(`docs/coverage/gates/vX.Y.txt`、台帳 id の部分集合)と「必須 E2E ケース」を**版の着手前に凍結**する。合格は対象 ID の **100%**。`wontfix` で分母を縮めるには理由+ユーザー承認(ADR 追記)が必要。`done` は台帳に `test_id`・`impl_rev`・`result`・`date` を持つ行のみ(列を追加する)。ブロックの対象表・管理画面範囲・プラグイン N 本は各版着手前の凍結物で、未凍結の版は着手しない。
2. **[Blocker] v0.1 に L1 の必須ゲート**: ①`docs/db-mapping.md`(12 表の列・型・既定値・索引・保存形式の対応表)②基準 WP のダンプ取り込み後、全表の行をキー単位で比較(欠落・変形 0)③書き戻したダンプを実 WP が読めること。これを P0→v0.1 の必須条件にする。
3. **[Blocker] L4 の成立・撤退条件**: L4 スパイク(別計画 docs/10 に起草)で、固定プラグイン 1〜2 本、PHP 実行・DB/FS アクセス・ジョブ・フックの副作用、隔離と権限制限 RPC を試す。**撤退条件**: 固定プラグインの主要機能が、隔離・制限を保ったまま E2E 一致しない場合、v0.5 を「L4 非対応を明記+TS SDK への移植ガイド」に再定義(ユーザー判断)。v1.0 の「全互換」は L4 判断後に確定し、それまで確約しない。
4. **[Major] SDK→Bridge の契約**: 共通フック契約(優先度、同順位の順序、引数、filter 戻り値、再入、登録解除、同期性)を定義し、**PHP との写像検証を SDK 契約凍結前に実施**。両言語間の契約テストを置く。
5. **[Major] compat_level 軸の分離**: フックは「SDK 機能(L3)」「フック契約(L3)」「PHP 実行互換(L4)」を別行・別軸にする。同名フックを実装しただけで L4 done にしない。
6. **[Major] セキュリティ・運用・SEO を版別ゲートへ**: v0.1=認可迂回・非公開情報漏洩、canonical/robots、sitemap の公開範囲、旧 URL の 301・ループ防止。v0.2=Application Passwords の失効・権限拒否、レート制限超過時の挙動。v0.3=SQLite+uploads の整合復旧、RPO/RTO の目標値と復旧演習。v1.0 に後送りしない。
7. **[Major] 台帳の粒度**: フックは「フック点」と「既定 callback 登録」を分離。REST は method×認証×副作用、DB は列・索引、テーマ機能は個別機能へ詳細化。dynamic 判定の抽出スクリプトを `tools/coverage/` に追加し再現可能にする。
8. **[Major] v0.6**: 診断は「対応/非対応/不明」の 3 値とし、対応保証は実行 E2E と併用(静的解析のみで保証しない)。
9. **[Minor] 未決の整理**: 目的(WP 置換エンジン)は ADR-020 で決定済み。未決なのは「最初の対象範囲(汎用のまま進めるか、特定サイトで絞るか)」のみ。
